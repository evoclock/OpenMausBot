# Pi coding readiness

A Pi provider instance may set `config.agentDir` to an absolute, reviewed, host-local Pi agent directory. When unset, the driver leaves Pi's agent-directory selection unchanged, including `PI_CODING_AGENT_DIR` if supplied by the host. When set, the directory is passed to the Pi RPC child and used for Pi's settings and local-model catalog. Nothing copies a personal profile or credentials. A configured directory must expose `poteto-mode-pi` to Pi's `get_commands`; otherwise a turn stops with an actionable error before creating its credential-bearing extension file. Skill discovery does not authorize work.

For a bot using Pi, Overview shows the skill and the development and independent-review roles for **that bot's working folder**. The read-only admin endpoint is `GET /api/pi/readiness?botId=<id>`. Place an owner-approved `.pi/pstack-model-roles.v1.json` in that working repository, using schema `pstack-model-roles.v1` and two distinct exact `provider/modelId` identities. Keep the file uncommitted: `.pi/` is ignored. `/skill:setup-pstack-pi` is the role-map setup flow; do not infer a model from an example's `null`. The reviewer pool should use current-generation capable models; the implementer pool should use economical models. Check data-route permission and credentials separately: model-list and `set_model` probes confirm Pi discovery and selection, not successful inference, worker dispatch, independent review, or a coding runner.

Bot standing instructions are edited in Settings → Soul. The canonical value is the bot record; a private `SOUL.md` is mirrored outside the bot-writable workspace and drift is shown rather than automatically adopted. Role-map setup does not edit Soul or grant the bot authority. The owner can describe the desired development and review workflow in Soul, but must separately authorize tasks and effects.

Preflight and role checks use the same Pi RPC commands (`get_commands`, `get_available_models`) as an isolated fixture. Test fixtures use a temporary agent directory and a fake CLI; they do not read the operator's home profile.
