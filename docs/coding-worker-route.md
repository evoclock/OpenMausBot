# Coding worker and reviewer route

The worker route calls the existing pstack playbook and asks a distinct reviewer to inspect its revision. Only pstack's acceptance result together with reviewer evidence can produce a verified outcome. Missing role selection, workspace mismatch, interrupted work, or an external repository blocks the default route. No fixed model identity appears in the code or repository; the host must read and verify the private project role map in the actual bot repository.

`WorkerHost` is a boundary for the trusted host to supply a verified private repository, scoped token, isolated Treehouse lease, Pi worker and reviewer in Herdr, and pstack verification. This module does **not** spawn panes, acquire a real worktree or invoke a live bot. The host must validate the repository's actual visibility and permissions independently of the run contract. It must reconcile interrupted commits and pushes before a retry. A blocked attempt releases its lease; a progressing or verified attempt retains its workspace until the owner merges or closes the PR. Only then return or prune that lease. Reviewer output is evidence, not permission.

No reviewer role was available in the inspected Herdr session, so an independent reviewer journey has not been proven.
