# Coding run composition

The opt-in coding-run runtime joins the existing outer task, trigger adapters, and worker/reviewer seam. It starts no run without a caller-supplied host and explicit trigger registration. A fixture drives one scheduled occurrence and one signed CI event through the full composition, then checks worker, reviewer and pstack-verification ordering and delivery deduplication.

The production server instantiates this runtime for operator-registered applied schedules and verified webhook deliveries. The WorkerHost uses isolated Treehouse leases and the existing server turn path for worker and reviewer roles; the composed-server fixture verifies that entry. The operator must configure wall-clock and spend ceilings for each origin bot in `codingRuns.bots`, or that unattended run blocks before a worker starts. Unpriced usage and expired deadlines produce terminal owner reports. Repository visibility and permissions still require independent host verification; the runner does not authorize public writes, merge or publication. GitHub secrets must come from private service configuration.
