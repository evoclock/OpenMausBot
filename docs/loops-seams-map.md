# Coding loops and product seams (Stage 1)

This is a contract map, not a claim that unattended coding works. The inner loop is the existing pstack Pi port operated by pi-agentic-driver; this repository must not alter that port. The outer loop adapts Geoffrey Huntley's [Ralph pattern](https://ghuntley.com/ralph/): repeat bounded attempts against a goal, reconcile effects, and stop on independently evidenced completion or an explicit hold. Pi Ralph loop and Cursor `/loop` are behavioral references, not dependencies. Only the owner merges.

## Outer ↔ driver contract to implement

The following is a proposed application protocol, **not an existing pi-agentic-driver API**. The product owns the immutable run contract (`id`, bot, repository, ref, success criteria and allowed effects in `server/run-contract.ts`) and a durable iteration ledger. The driver owns the pstack task's durable steps, its last committed step and worker/reviewer outputs. A single host owns each SQLite harness; the product does not write the driver's checkpoint. The host must verify the active Pi profile, roles, isolated workspace, repository permissions and credential reference before dispatch (`docs/pi-coding-readiness.md`, `docs/coding-worker-route.md`).

| Operation | Request / result | Restart and idempotency rule |
| --- | --- | --- |
| Start | Outer supplies immutable contract, run ID, iteration ID and stable invocation key; driver returns a durable task identifier or a typed refusal. | Duplicate key with identical input returns the same task; mismatched input refuses. Record task ID before acknowledging start. |
| Resume | Outer supplies task ID and last observed durable step ID after reconciling any uncertain effects; driver resumes only from its persisted committed step. | Never turn `blocked` into `running` solely because a process restarted. A committed step ID is evidence of internal progress, not proof that an external push did or did not happen. |
| Status | Read-only snapshot: task ID, committed step ID, phase, state and last outcome/effect receipt references. | Polling has no execution side effects; version or sequence prevents stale updates from overwriting newer state. |
| Report | Driver supplies correlated iteration/task/step ID, exact revision, scoped evidence and outcome (`progress`, `verified`, `blocked` or failure); outer records one report and delivers progress/final result. | Dedupe by task ID and report ID; require independent verification evidence before `done` (`server/outer-runner.ts`). A receipt or self-report alone is not a verdict. |
| Cancel | Outer sends run/task ID and reason; driver acknowledges stop or reports an already terminal task. | Repeat cancel is safe. Preserve leases and unknown outward effects for reconciliation; no replay after an uncertain cancellation. |

Use the existing `requestId = runId:iteration` and `InnerLoop.invoke(contract, iteration, requestId, signal)` seam (`server/outer-runner.ts`) as the outer-side adapter, not a second scheduler. `server/inner-worker-route.ts` documents idempotent acquisition by request ID, but the actual host must prove it. `server/run-triggers.ts` derives stable IDs for duplicate routine occurrences and signed webhook deliveries. A new iteration needs a new key; a retry of the same iteration retains its key and must first inspect workspace, commit, remote ref and PR state. At the outward boundary, persist intent and receipt with stable effect ID; on missing/ambiguous receipt, park and ask for reconciliation rather than reissuing a push, PR or approval. The two databases in `server/outer-runner.ts` (`runtime.db` and `coding-runs.sqlite`) do not share an atomic commit: reconcile a stored iteration that is ahead of its durable task checkpoint before moving forward.

The package pinned at `@earendil-works/pi-durable@1.0.4` exports `defineTask`, `createRegistry`, `defineExtension` and `Harness` from its root, and `openNodeSqliteStorage` from `@earendil-works/pi-durable/storage/sqlite/node` (`package.json`, `dist/index.d.ts`, `dist/storage/sqlite/node.d.ts`). Its `Harness.open` creates the harness; `Harness.root` returns the conversation; `Conversation.commit` with `tx.createTask` creates a task ID; `Harness.resume` enables scheduling; `Harness.getTask` and `Harness.inspect` read persisted task state; `Harness.waitForTask` waits for terminal settlement; `Harness.abortTask` marks/signals a task for its abort phase (`dist/harness/types.d.ts`, `dist/session/transaction.d.ts`). A phase persists its checkpoint or terminal outcome with `TaskRuntime.commit`, and `TaskRuntime.memo` can store a durable first-writer-wins value (`dist/types.d.ts`). `Harness.resume` is not a per-task resume command: it enables scheduling, and `waitForTask` also enables scheduling. An interrupted phase can run again from its last committed checkpoint; that is why the current adapter parks a previously `running` invocation rather than blindly replaying it (`server/outer-runner.ts`).

The outer runner's `start`, `resume`, `wait`, `get` and `close` are **local wrapper methods**, not pi-durable exports. There is no package-level start/status/report/idempotent-effect protocol for the driver, nor a built-in guarantee that `tx.createTask` deduplicates a caller's run ID: the proposed stable-key lookup, correlated reports, durable external-effect receipts and step IDs require application code. The outer task ID and checkpoint `sequence` are available today; a driver-owned durable step ID is not exposed by this adapter. `Harness.abortTask` exists, but cancellation of an outer run and safe reconciliation with the driver are not wired. The driver-side start/resume/status/report/cancel endpoints require inspection in pi-agentic-driver-agents; changes there belong in that repository, not here.

Stage 2 must prove a real kill/restart across the invocation boundary without repeating work, including the uncertain outward-effect case. Stage 3 must enforce destination-specific push and draft-PR policy. Stage 4 must exercise a scripted unattended end-to-end run with deliberate crash and evidence. Each stage waits for the preceding stage's owner merge; this document grants none of those effects.
